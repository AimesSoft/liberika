# v0.1.8 API とドキュメントの整合性監査

[中文](v0.1.8-api-alignment.md) · [English](v0.1.8-api-alignment.en.md)

監査日：2026-09-07。リリース基準：`91406690405f87f03b9ddddbc48179426bf5abea`（v0.1.8）。修正は `3d79d0d87c363576b3aeb9ecfc6a3ea8f9834653` に基づきます。

## 結果と修正

v0.1.8 にはバインディングとドキュメントの欠落があり、「全プラットフォームが整合済み」とは言えません。この作業は再生コアを変更しません。

| 層 | 発見 | 対応 |
|---|---|---|
| OpenHarmony Flutter | Dart は `videoAlphaMode` を送るが ArkTS と N-API の作成関数が捨て、コアは常に opaque を受け取る | 第 4 引数と型宣言を追加。旧 3 引数呼び出しは opaque が既定 |
| 独立 OHPM SDK | 設定インターフェースと N-API 作成関数に透過動画の引数がない | 任意設定を追加し `ErikaPresenterConfig.video_alpha_mode` に渡す |
| ヘッダーコピー | OHPM コピーに Windows Flutter texture getter がなく、Flutter コピーは正しい | 主ヘッダーと同期。getter は Windows 専用であり、OHOS runtime に必要な機能の欠落ではない |
| 3 言語 C API ドキュメント | Windows texture getter が欠落し、同期 open を非同期と記述 | インターフェース、COM 参照の所有権、エラー動作、同期 open の制約を追加 |
| ABI 説明 | v0.1.7 の設定は 12 バイト、v0.1.8 は 16 バイトで、値渡しでは混用できない | 3 言語のリファレンスに対応するヘッダー、バインディング、ライブラリの同時再ビルドを明記 |
| アーキテクチャと Flutter ドキュメント | 関数数を 88 と固定し、一部のプラットフォーム一覧に Windows texture がない | 古い数を削除し Windows 専用エクスポートの境界を明確化、3 言語の説明を同期 |
| 日本語スクリーンショット文書 | 「弾幕なし」と「弾幕あり」が矛盾 | 実装と英中の説明に合わせ、動画と字幕のみ、弾幕なしに統一 |
| 独立 liberika-swift SDK | main は v0.1.7 を使用し、作成関数は 3 フィールドの設定、公開 open に read-ahead 引数がない | 確認済みだが本リポジトリでは未修正。独立 SDK の更新コミットと Apple ビルド検証が必要 |

コア wgpu の `video_uniforms_for_frame`、論理動画幅、透明クリアはすでに alpha mode を使用します。OHOS AVCodec の Vulkan 変換結果もこの合成パスに入るため、引数の欠落はバインディング層で発生しています。これは OHOS 透明ウィンドウや Flutter compositor の実機受け入れが完了したことを意味しません。

## PR の範囲

v0.1.7 から v0.1.8 までのマージ済み 29 PR を分類して確認しました。

- API、バインディング、GPU 合成：#105、#119、#123、#124、#126、#127、#128、#129。#127/#128 で Apple 設定ミラーは修正済み。今回は OHOS 引数と #129 後に欠落したヘッダーコピーを補完。
- コア再生動作：#82、#115、#121、#122、#131。新しい C 入口は不要で、これらの修正は変更しません。
- 成果物、SDK 公開、ドキュメント：#98、#99、#100、#101、#102、#103、#104、#106、#108、#109、#110、#111、#112、#113、#114、#117。パッケージング成功と各プラットフォームのバイナリ/デバイス実行検証は別の結論です。

本バージョンの新規 C 関数は 7 個：2 つの `open_with_options`、`create_with_output_mode_and_alpha`、`attach_flutter_texture`、`set_flutter_texture_buffer`、2 つの Windows `IUnknown` getter。主ヘッダーの 98 関数は Rust エクスポートの名前と引数/戻り値型に対応します。検査はソース中のプラットフォーム実装と非対応プラットフォームの stub を含みます（opaque presenter ポインタは ABI 等価として扱う）。すべての構造体レイアウトや全ターゲットのリンク結果を証明するものではありません。

新しい `ErikaOpenOptions` のフィールド順と幅は Rust と Apple 3 プラットフォームの手書きミラーで一致します。headers ポインタ、ポインタ幅の count、u64 read-ahead、3 つの u64 reserved です。変更後の `ErikaPresenterConfig` は i32/f32/i32/i32 で Apple ミラーと一致します。Windows と Android の作成バインディングは alpha mode を渡し、HTTP read-ahead は Apple、Windows、Android、OHOS の JSON 経路で受け取ります。

## 検証記録と限界

- 5 項目の対象テストが成功：ヘッダーミラー、関数名、C/Rust 関数シグネチャ、ArkTS 引数チェーン、2 つの元の N-API `NativeCreate` 関数のホスト模擬実行。
- 元の作成関数テストはリポジトリ関数を直接コンパイルし、偽 N-API 入力と presenter 捕捉先で、4 引数 alpha=1、3 引数の既定 alpha=0、他の設定が失われないこと、3 引数未満を拒否することを確認します。v0.1.8 の旧 2 関数はいずれも alpha=1 のアサーションに失敗し、修正版は成功しました。このテストは OHOS N-API SDK ビルドや実機実行の代わりにはなりません。
- ダウンロードした v0.1.8 `erika-capi-openharmony-arm64.zip` 内の `liberika_capi.so` を `llvm-nm -D --defined-only` で検査し、想定 96 C シンボルがすべて存在し、余分な C シンボルはありませんでした。2 つの `erika_presenter_windows_*_iunknown` は Rust の Windows cfg 限定で、OHOS に存在すべきではありません。
- 他プラットフォームのリリースライブラリの全シンボル表は今回は読んでおらず、未確認成果物の全量保証はしません。
- 独立した `AimesSoft/liberika-swift` main `96159140b3be7cd4623ffb6f4d009502422d66ae` を GitHub API で確認しました。`Package.swift` の binary target は v0.1.7 を指し、`ErikaPlayer.swift` は 3 フィールド設定を作成、公開 open は HTTP headers のみで read-ahead がありません。対応する旧ライブラリを使用しているため、これだけで runtime ABI 混用とは言えませんが、v0.1.8 には未整合です。ダウンロード URL の変更だけでは足りず、設定初期化と公開パラメータを更新し Apple ビルドを検証する必要があります。
- `git diff --check` が成功。回帰チェックは既存 Ubuntu quality job に追加し、新しい CI マトリクスは設けません。今回はリモート CI を起動せず、公開済み v0.1.8 成果物も変更していません。

ローカル実行：`CXX=g++ python3 packaging/tests/test_api_alignment.py -v`。修正は今後マージし、更新した ArkTS と N-API bridge を含む Flutter/OHPM パッケージを公開して初めてレジストリ利用者に届きます。コアライブラリの更新だけでは旧ブリッジによる引数欠落は修正できません。
