# Doctor-X S01E01：macOS で断続的に発生する音割れの調査

[中国語の調査記録](doctorx-audio-2026-10-26.zh.md)の翻訳です。

日付：2026-10-26。基準：`f83ccdb7bf9e759851d42e11af2e956dd5194c6b`、ブランチ：`codex/doctorx-audio`。調査機の NipaPlay は 1.11.10、その Flutter 依存は `erika_flutter 0.3.0` でした。

この Mac で Doctor-X 第1シーズン第1話を再生中、46 分と 48 分付近で顕著な音割れが発生し、MDK に切り替えると正常でした。巻き戻して再生し直すと位置が変わり、発生しない場合もあることをユーザーが確認しています。

CoreAudio 出力に一つの不具合が確認されました。callback で部分的な underflow が起きるだけで、出力ブロック全体を `OUTPUT_IS_SILENCE` にしていました。有効な PCM の先頭部分はキューから取り出され音声クロックに計上済みですが、CoreAudio が無音としてスキップする可能性があります。この不具合は短い underflow による音の途切れを拡大し得ます。修正では PCM をまったく読み取れなかったときだけ無音フラグを設定し、その後 PCM が得られたらクリアします。

ユーザーが音割れを聞いた瞬間の NipaPlay の underflow 記録は取得できていないため、確認されたコード上の欠陥と今回の症状を結び付ける直接の実行時証拠はまだありません。バッファー枯渇の引き金も未特定です。

## メディアとデコードの検証

サンプルはローカルにマウントされたメディアディレクトリ内の `Doctor.X.Surgeon.Michiko.Daimon.S01E01.2012.1080p.Netflix.WEB-DL.AVC.AAC.2.0-DBTV.mkv` です。長さは 3508.822 秒、映像は H.264、音声は HE-AAC・48 kHz・ステレオ。システムの既定出力は 48 kHz の MacBook Pro 内蔵スピーカーです。このエピソードではサラウンドのダウンミックスは行われません。

| 確認 | 結果 |
|---|---|
| 標準 FFmpeg で 40:00–50:00 をデコード | デコードエラーなし、ピーク 0.936851（約 −0.567 dBFS）、NaN/Inf なし |
| 約 45:00–49:00 の AAC 圧縮パケットを直接抽出 | Matroska の seek にプリロールが含まれるため、実際のサンプルは 245.546 秒 |
| Erika `PlaybackSession` でサンプルを f32 PCM に出力 | ステレオ 11,786,240 フレーム、23,572,480 サンプル値 |
| 標準 FFmpeg の f32 PCM と比較 | 長さが等しく、各サンプルが完全一致。最大誤差と RMS 誤差はいずれも 0 |
| Erika PCM のピークと時刻 | ピーク 0.644198120、オーバーレベル、非有限値、2 ms 超の PTS 不連続はいずれも 0 |

両 PCM の SHA-256：


この比較はユーザーが指摘した区間を含み、リアルタイム供給と出力経路を引き続き調べる根拠になります。MDK のデコード出力はサンプル単位で比較していません。

## 回帰と実行時チェック

追加した CoreAudio 回帰テストではリングバッファーに PCM 2 フレームを書き込み、4 フレームを要求して、有効な先頭部分、ゼロ埋めの末尾、無音フラグ、読み取りフレーム統計を検証します。続いて完全に空のバッファーと、PCM 補充後の音量ランプを検証します。

旧条件 `underflow_frames > 0` では有効な先頭部分が誤って無音とされたためテストが失敗しました。`frames == 0` に変更後、`cargo test -p erika audio -- --nocapture` の 77 テストが通過しました。

別の診断プログラムで Presenter、VideoToolbox、Metal テクスチャー、実際の CoreAudio 出力を動作させ、視聴を妨げないよう音量は 0 にしました。修正前に 47:30 から 75 秒実行し、音声の読み取りフレームは進み続け、underflow とドロップフレームのカウントはともに 0 でした。ユーザーの断続的な不具合はこのテストでは再現していません。

全負荷チェックでは同名の弾幕 XML、埋め込み字幕、1920×1080 Metal テクスチャーも追加しました。最初の 45:45 からの seek は worker barrier の 2 秒タイムアウトに達し、再生が始まらなかったため、音声の検証には使えません。45:55 からの再試行は 165 秒、約 48:39 まで実行し、underflow とドロップフレームはともに 0 でした。この回は修正後のコードで通常再生経路を検証しましたが、underflow が発生していないため故障が消えたことの証明にはなりません。ログは調査機の `output-danmaku-retry.log` です。

## 再テスト

修正ファイルは `crates/erika/src/apple.rs` です。この調査ではインストール済み NipaPlay のランタイムを置き換えていません。次のアプリ内再テストでは音声 underflow、render tick の所要時間、バッファー量を同時に記録し、音割れとバッファー枯渇が同時に起こるか確認してください。途切れが続く場合は、描画スレッドの供給遅延とメディア読み込み遅延を区別します。

元の PCM、メディア区間、一時的なプローブソース、修正前後のテストログ、実行時出力ログは調査機の `out/doctorx-audio-2026-10-26/` に保管し、リポジトリのテスト素材としてコミットしていません。リポジトリ内の回帰テストは合成 PCM を使用し、上記 Cargo コマンドで独立して再現できます。
