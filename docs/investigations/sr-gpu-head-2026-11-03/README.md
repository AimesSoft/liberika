# Vulkan 半精度空间末层优化

新加入的半精度空间末层，使 RTX 5060 Ti 上 ArtCNN C4F16-DN/C4F32-DN 在
1920×1080 输入下的整网 GPU 耗时进一步降低 **7.4–8.0%**。实现位于
[`head_spatial_half.comp`](../../../crates/erika/src/renderer/vk_coopmat/head_spatial_half.comp)，
路径选择与系数打包位于
[`d3d11_vk_coopmat.rs`](../../../crates/erika/src/renderer/d3d11_vk_coopmat.rs)。

## 测量条件与结果

环境为 Windows、RTX 5060 Ti 16 GB、驱动 616.56。基线源码为
`63afdc5eadbb5c494dc9a872a40337fd341026a4`。输入是 1080p 亮度图，输出放大 2 倍。
计时覆盖完整 **D3D11 → Vulkan → D3D11 GPU 区间**，包含输入复制与同步。
每个候选预热五次，再执行三轮、每轮 15 个样本，正反交替候选顺序。
汇总取三轮中位数的中位数，正式计时时关闭分层 profiling。

| 模型 | 矩阵层累加 | 原末层 | 半精度末层 | 整网耗时下降 |
|---|---|---:|---:|---:|
| C4F16-DN | fp32 | 3.623776 ms | 3.354048 ms | 7.44% |
| C4F32-DN | fp32 | 7.213536 ms | 6.661504 ms | 7.65% |
| C4F16-DN | fp16 | 3.383840 ms | 3.113696 ms | 7.98% |
| C4F32-DN | fp16 | 6.386528 ms | 5.874560 ms | 8.02% |

两种矩阵配置中的原向量末层均使用 fp32 累加；新末层使用 fp16 系数与累加器，
其他层保持所选精度。桌面活动会带来样本波动，完整数据保存在
[fp16 矩阵累加记录](data/results_confirm.json)与
[fp32 矩阵累加记录](data/results_confirm32.json)。

## 从计算图定位热点

一层卷积在整幅输入图像上的有效浮点运算量为：

$$F=2HW C_{out}\sum_i C_i k_i^2.$$

线性层合并后，末层把一个 5×5 特征卷积分支和一个 5×5 亮度分支组合成四个输出通道，
再分别映射到 2 倍输出的四个子像素。这个形状的输出通道很窄，宽矩阵块会浪费大量
输出通道容量，因此现有实现为它选择向量 ALU 路径。

分层时间戳显示，在 fp16 矩阵累加配置下，C32 的中间卷积合计约 2.79 ms，
末层及边缘修正约 2.13 ms，整个 Vulkan 区间约 6.00 ms。
末层占比约 **35%**，因此成为这轮优化的重点。

寄存器内的 16×16×16 矩阵标定得到 fp16/fp32 累加分别为 **92.101/45.948 TFLOPS**，
128 MiB 复制得到 **324.712 GB/s**。这些结果提供了本机同形状算术与传输的对照。
实际卷积还包含搬运、寻址、激活和写回成本，后续优化以逐层及整网计时确定收益。

## 特征布局与协作加载

特征缓冲按 16 个通道分块。令 $P=WH$，通道 $c$、像素 $p$ 对应的半精度元素索引为：

$$I(c,p)=16P\lfloor c/16\rfloor+16p+(c\bmod16).$$

原加载器让相邻线程读取同一通道的相邻像素。新加载器让相邻线程读取同一像素的连续通道，
与全局特征布局对应，再将数据写入按通道分平面的共享内存。

对于通道块宽 $C_b$、8×8 输出块与卷积核宽 $k$，令输入块边长 $S=8+k-1$、面积 $A=S^2$。
线性加载索引 $i$ 映射为：

$$c=i\bmod C_b,\qquad p=\lfloor i/C_b\rfloor,$$

共享存储索引为 $c(A+1)+p$。每个通道平面末尾补一个元素，调整相邻平面的间距。
卷积仍按原来的通道、核行与核列顺序累加。

## 半精度运算与系数打包

每组四个系数 $(w_0,w_1,w_2,w_3)$ 保留原有 16-byte uniform 槽。
令 $h(w)$ 表示转换为 fp16 后的 16 位编码，前两个字存放：

$$u_0=h(w_0)\;|\;(h(w_1)\ll16),\qquad
u_1=h(w_2)\;|\;(h(w_3)\ll16).$$

shader 将这两个字重解释为 `f16vec4`，用 fp16 FMA 完成四个输出通道的累加。
共享输入也改为 fp16。偏置、边缘修正、子像素输出以及亮度范围和基底重建沿用原路径。
共享内存占用从 **9,216 降到 4,640 bytes**；系数缓冲仍为 16 KiB，以保持原索引步长。

驱动报告的末层资源与分层计时如下：

| 模型 | 寄存器数：原 → 新 | 二进制 bytes：原 → 新 | 末层耗时：原 → 新 |
|---|---:|---:|---:|
| C4F16-DN | 25 → 26 | 48,384 → 34,816 | 1.056192 → 0.785824 ms |
| C4F32-DN | 28 → 28 | 90,112 → 63,488 | 2.127744 → 1.607904 ms |

末层计时包含边缘修正，来自单独开启 profiling 的运行。
约 **25%** 的末层耗时下降，与整网约 **0.27/0.52 ms** 的节省相吻合。
资源数据见 [half-stats.log](data/half-stats.log)，分层数据见
[原末层](data/profile.log)和[新末层](data/half-profile.log)。

## 数值结果与默认选路

两套内置 DN 模型都与原始、未折叠的 CPU 网络比较。每种矩阵累加精度完成 62 项扩展比较，
覆盖黑图、白图、棋盘格、单点、噪声、渐变和平滑/边缘输入；Full/Limited 亮度范围；
正常分块与强制 32×16 分块；1080p 输出的左上、中央与右下区域。
CPU 参考裁剪保留所需感受野的完整上下文。另外检查了基础 5×3 与 2×2 输入。

| 矩阵层累加 | 各案例中最大的 MAE | 最大单点误差 |
|---|---:|---:|
| fp16 | 0.00058939 | 0.00343108 |
| fp32 | 0.00046760 | 0.00294208 |
| 现有验收阈值 | 0.002 | 0.03 |

124 项候选比较全部通过，输出均为有限值。半精度会改变舍入，以上是测试输入中的实测误差。
原始记录见 [quality.log](data/quality.log) 与 [quality32.log](data/quality32.log)。

NVIDIA 上对这两套已验证的内置图默认启用新末层。选择时先匹配模型名称，再比较完整图与权重，
同名但权重不同的自定义模型保留其原有精度策略。
`ERIKA_VK_FP16_HEAD=0` 选择原 fp32 末层；设为 `1` 时，允许其他厂商在满足相同图与能力检查后使用。
`ERIKA_VK_FP16_ACCUMULATION` 独立控制矩阵层累加精度。

## 生产后端接入复核

将 shader、系数打包与默认选路接入生产后端后，用独立 Windows harness 再次检查。
生产后端的非测试实现原样使用，只额外暴露诊断成员；catalog 适配加载同样的两套真实 ESR
并使用同一线性合并函数。日志确认基线选择 `half_head=false`，新默认路径选择 `half_head=true`。

两项完整模型匹配/系数布局单元测试通过；两种矩阵精度的 **124 项数值比较全部通过**。
随后按相同三轮、每轮 15 样本的口径复核性能：

| 模型 | 矩阵层累加 | 原末层 | 半精度末层 | 整网耗时下降 |
|---|---|---:|---:|---:|
| C4F16-DN | fp32 | 3.620544 ms | 3.360000 ms | 7.20% |
| C4F32-DN | fp32 | 7.417760 ms | 6.647968 ms | 10.38% |
| C4F16-DN | fp16 | 3.384736 ms | 3.114880 ms | 7.97% |
| C4F32-DN | fp16 | 6.366496 ms | 5.846976 ms | 8.16% |

两轮实验均确认收益，本文以首轮稳定确认的 **约 7–8%** 作为汇总结论。
生产 SPIR-V 使用 `glslc --target-env=vulkan1.3 -O` 生成，与成功实验的 SPIR-V 逐字节一致。

## 其他候选方案与消融结果

这轮实验按布局、运算精度和共享存储逐步拆分：

- 连续通道加载配合 fp32 运算，整网耗时下降 1.6–2.8%。
- 再加入 fp16 系数与累加器，继续降低末层成本；共享输入改为 fp16 后得到最终采用的实现。
- 相邻输出行的矩阵复用，将两行的 B 片段加载从 18 次降到 12 次，四行从 36 次降到 18 次。
  数值检查通过，但 C32 整网慢了 30–45%，中间层寄存器从 80 增到 112/140。
  因此保留横向 resident kernel。
- 更复杂的共享内存置换增加了寄存器和共享存储占用，未带来收益；最终使用简单的通道平面补齐。

消融样本见 [行复用](data/results_rows.json)、[加载布局](data/results_heads.json)、
[半精度分解](data/results_half.json)。这次优化保持训练网络的结构，
通过改善末层数据布局和运算实现得到额外收益。

## 复现方式

在已具备仓库原生依赖的 Windows 环境，以单测试线程运行 release 测试：

```sh
cargo test -p erika --release --lib renderer::d3d11_vk_coopmat::tests::vk_half_head -- --test-threads=1
cargo test -p erika --release --lib renderer::d3d11_vk_coopmat::tests::vk_remaining_catalog_modes -- --test-threads=1
```

shader 重新编译命令与诊断开关见
[`vk_coopmat/README.md`](../../../crates/erika/src/renderer/vk_coopmat/README.md)。
保持模型、帧尺寸和矩阵累加精度相同，对比 `ERIKA_VK_FP16_HEAD=0` 与 NVIDIA 上未设置该变量的默认路径。
本报告的成对计时与生产接入复核使用独立 D3D11/Vulkan harness，稳态计时不含媒体解码和 shader 编译。
